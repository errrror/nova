# Commit rules

Finish final Review, the time-log audit, applicable external/resource handling, the message, and enabled Token reporting. Save commit-preparation facts in the overview before authorized git add/commit/push. Stage only this task's files explicitly; preparation is not a successful commit.
Use project rules for message format, issue IDs, commits per MR, and amend policy. Without a project format use `<type>(<scope>): <subject>`; types include feat/fix/perf/refactor/docs/test/chore.
Incomplete or unsupported times require returning to and redoing the missing phase; do not record a missed entry and continue.
Do not commit credentials, raw token.json, or temporary test outputs. Respect no-commit/no-push boundaries. Generating a Token report does not authorize extra Git operations.
