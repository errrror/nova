# Project Profile

- 扩展：generic
- 扩展版本：2.0
- 流程：6 步
- 语言/解释器/框架版本：引用项目实际规则，不假定最新版本
- 项目规则：仓库现有规则（使用系统内置默认 SOP，不修改仓库规则文件）
- 技术文档：对话已选平台知识库与仓库现有文档（README.md / docs/）
- 分支与默认基线：按项目 Git 约定

## 质量门禁

UT 命令、增量覆盖率命令、lint/格式化及 IT 命令：接入项目时按仓库配置与 CI 填写，禁止臆造。
默认增量行/分支阈值：普通业务 80%/70%，核心逻辑 90%/80%，高风险基础设施 90%/85%；Glue/Adapter/简单 CRUD 行 70%～80%，分支放宽值及理由须记录。生成代码/声明式配置凭证据排除，无可执行分支记 N/A。项目更严格规则继续生效。

## 执行适配

- Clarify：Core 指引，加本项目相关领域约束。
- Implement：遵守 `.wally/rules/` 下的项目规则。
- Deploy：由客户在 `.wally/config.json` 的 deploy 中填写 command 或 guide；未配置自动跳过，已配置时按实际环境、授权、生效检查及回滚执行。
- IT：由客户在 `.wally/config.json` 的 it 中填写 command 或 guide 及结果判定规则；未配置自动跳过。已配置但缺环境/工具、执行失败时如实阻塞，不改成跳过或通过。
- Review：项目编码规则、版本矩阵及 `.wally/review.md`。
- Commit：项目已有提交规范（按授权提交业务源码）；Commit/Push 分别按用户授权执行。
- 外部需求系统/资源释放/云端委托：按项目需要配置，无配置不自动发起。
- Token：builtin；未启用不记作零消耗。

## 项目自定义

填写项目实际命令、门禁来源和专项限制。初始化/升级保留整个文件；变更预设通过对比新版本人工合并，不覆盖定制。


初始化时从项目实际文件补齐执行指引，记录来源、工作目录、命令、前置依赖、结果判据及清理/回滚。必要信息缺失时在 `.wally/config.json` 设可选 `readiness: pending` 并列出具体 `gaps`，向用户询问并等待补齐；阶段标为 BLOCKED，不能自动跳过或因指南路径非空而启用。静态核验完整后才设 ready，不代表执行通过。未带 readiness 的旧配置仍兼容 command/guide 判断。
