# Clarify guidance

Locate this task's `01-clarify.md`. Read existing requirements and user constraints; establish target users, scenarios, scope, measurable success criteria, and dependencies. Validate sufficient user-provided inputs directly instead of repeating an interview.

Ask short, focused questions only about gaps that affect implementation. Allow corrections to assumptions and continue independent research while waiting. Check key assumptions, failure scenarios, minimum deliverable scope, and conflicting constraints. Do not mandate a fixed number of discovery/challenge rounds or additional confirmation ceremonies.

For bugs and performance work, record the failure criterion, input and initial state, observed and expected behavior, existing reproduction/baseline evidence, and environmental limits. Load specialist project checks only when relevant.

Record facts, decisions, risks, and sources in this task. Do not overwrite other tasks or create a duplicate PRD. Update existing useful documents only within scope; discussion alone does not authorize artifact changes. Resolve major business questions before Plan; use the interaction rules to determine whether user input is required.
